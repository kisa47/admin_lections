Языки разметки

Языки разметки и форматы сериализации данных, используемые для конфигураций, эволюционировали от строгих корпоративных стандартов к форматам, оптимизированным для чтения человеком. Выбор конкретного формата зависит от сложности структуры, требований к типизации и экосистемы, в которой работает программа.

Общие принципы

Несмотря на различия в синтаксисе, все языки разметки для конфигураций преследуют общие инженерные цели и подчиняются схожим правилам работы со специальными символами. Эти принципы обеспечивают предсказуемость, читаемость и возможность автоматической обработки файлов.
  • Человекочитаемость.
  • Декларативность.
  • Иерархичность.
  • Типизация данных.
  • Предсказуемость (идемпотентность).
  • Модульность и переиспользование.

Спецсимволы.

Специальные символы используются для обозначения структуры данных. Если их нужно использовать внутри самих данных (например, запятую внутри строки), применяются правила экранирования.
Спецсимволы разделяются на:
  • Разделители структур
  • Кавычки и строковые литералы
  • Символы экранирования
  • Комментарии
  • Подстановка переменных и ссылки

Разделители структур.

Разделители структур — это базовые символы, которые определяют архитектуру данных в конфигурационном файле. Они указывают парсеру, где заканчивается одно значение и начинается другое, где находится иерархический уровень и как группируются элементы. 
{
	"server": {
		"listen": "0.0.0.0",
		"port": 8080,
		"urls": [
			"host1.example.ru",
			"host2.example.ru"
		]
	}
}

Кавычки и строковые литералы.

Кавычки в конфигурационных файлах выполняют две основные функции: определение границ строкового литерала и управление интерпретацией специальных символов внутри этой строки.
path1: "C:\\new_folder"
path2: 'C:\new_folder' # Результат будет идентичным
text: |
  Это многострочная
  строка без кавычек

Символы экранирования

Экранирование (escaping) — это механизм, позволяющий вставить в строковый литерал символы, которые иначе были бы интерпретированы как часть синтаксиса (структуры) или были бы невидимы (управляющие символы).
Обратная косая черта (\) называется символом-экраниатором (escape character). Она сообщает парсеру, что следующий за ней символ нужно трактовать особым образом.
path1: "C:\\new_folder"
path2: 'C:\new_folder' # Результат будет идентичным
vandor1: 'LLC "Dacom M"'
vandor2: "LLC \"Dacom M\""  # Результат будет идентичным

Комментарии

Комментарии в конфигурационных файлах служат для пояснения логики настроек, временного отключения директив (закомментирования) или оставления пометок для других разработчиков. Поддержка комментариев — это одно из главных отличий форматов, ориентированных на человека (YAML, TOML), от форматов машинного обмена (JSON).
# Настройки базы данных
[database]
host = "localhost" # локальный инстанс
port = 5432
# debug = true # Не применится, так как "закомментировано"

Подстановка переменных и ссылки

Подстановка переменных и ссылки (references) позволяют избежать дублирования данных в конфигурационных файлах, собирать настройки из разных источников и создавать переиспользуемые шаблоны. 
# Определяем общие настройки
common_settings: &defaults
  timeout: 30
  retries: 3
  log_level: info

# Используем их в сервисе А
service_a:
  <<: *defaults # Вливаем все поля из defaults
  host: db-a.internal

# Используем в сервисе Б с переопределением одного поля
service_b:
  <<: *defaults
  log_level: debug # Переопределяем только уровень логирования

INI


Формат INI (Initialization File) — это один из старейших текстовых форматов для хранения конфигураций. Он зародился в операционных системах Windows, но благодаря своей предельной простоте стал стандартом для многих кроссплатформенных приложений. 
; ===========================
; Настройки веб-сервера
; ===========================
[server]
host = 127.0.0.1
port = 8080
; Режим работы: development или production
environment = development

[database]
; Подключение к основной БД
type = postgresql
host = db.internal.local
port = 5432
name = app_db
user = app_user
password = secret_password

; Пути к данным
[paths]
log_dir = /var/log/myapp
temp_dir = /tmp/myapp

Секции (Sections)

Имена секций пишутся на отдельных строках и заключаются в квадратные скобки [ ]. Все директивы, идущие после заголовка секции, относятся к ней, пока не начнется следующая секция. 
; настройки для сервера
[server]

; настройки для БД
[database]

; Пути к данным
[paths]

Директивы (Key-Value pairs)

Это пары «ключ = значение». Знак равенства является разделителем. В классическом INI пробелы вокруг знака = обычно игнорируются, но для читаемости их принято ставить. 
host = 127.0.0.1
port = 8080
; Режим работы: development или production
environment = development

Комментарии

Обычно начинаются с точки с запятой ;. Всё, что следует за этим символом до конца строки, игнорируется. Современные парсеры часто поддерживают и символ решетки #. 
host = 127.0.0.1
; ===========================
; Настройки веб-сервера
; ===========================
; Режим работы: development или production

Преймущества

  • Простота написания: Не нужно помнить про запятые (как в JSON), кавычки для каждого ключа (как в JSON) или отступы (как в YAML).
  • Читаемость: Для плоских настроек (ключ-значение) это самый наглядный формат.
  • Легковесность: Парсер для INI можно написать в 10–15 строк кода на любом языке.

Недостатки

  • Нет вложенности: Нельзя естественным образом описать список словарей или глубоко вложенные объекты.
  • Нет типов: Все значения — строки. Число 8080 и строка "8080" для INI неразличимы.
  • Нет возможности задать многострочное значение.

TOML

TOML (Tom's Obvious, Minimal Language) — это современный формат конфигурационных файлов, созданный Томом Престон-Вернером (сооснователем GitHub). Его главная цель — быть минималистичным, очевидным для человека и при этом абсолютно однозначным для парсера, избегая «магического» угадывания типов, как в YAML.

# Метаданные проекта
[project]
name = "my-awesome-app"
version = "2.4.1"
description = """Это многострочное описание
моего приложения, которое читается
очень легко."""

# Зависимости (массив строк)
dependencies = [
    "fastapi>=0.104.0",
    "uvicorn[standard]>=0.24.0"
]

# Настройки сервера
[server]
host = "0.0.0.0"
port = 8080
# Литеральная строка для сложного пути или regex
static_path = '/var/www/assets/(.*)'

# Массив объектов (таблиц)
[[database.replicas]]
host = "db-replica-1.local"
priority = 1

[[database.replicas]]
host = "db-replica-2.local"
priority = 2

Секции (Sections)

Имена секций пишутся на отдельных строках и заключаются в квадратные скобки [ ]. Все директивы, идущие после заголовка секции, относятся к ней, пока не начнется следующая секция. 
# настройки для сервера
[project]

# Настройки сервера
[server]

Вложенные таблицы (Вложенные секции)

В TOML вложенные таблицы (аналоги вложенных объектов в JSON или словарей в Python) создаются двумя основными способами: через заголовки с точечной нотацией и через ключи с точками. Главная особенность TOML — строгая типизация и запрет на переопределение типов (нельзя превратить число в таблицу). 
[server]
host = "0.0.0.0"

# Создается таблица server.tls
[server.tls]
enabled = true

# Создается глубокая вложенность server.tls.validation
[server.tls.validation]
check_revocation = true

# Это создает корневую таблицу, в которой есть ключ database.host
database.host = "localhost"
database.port = 5432

# Это превращает ключ database в таблицу (если она еще не была определена как строка)
database.name = "app_db"

Массивы таблиц

Массивы таблиц - это одна из самых мощных возможностей TOML, позволяющая описывать списки объектов (например, список пользователей, серверов или товаров). Для создания такого массива используются двойные квадратные скобки [[ ]].
[[products]]
name = "Молоток"
sku = 738594937

[[products]]
name = "Гвоздь"
sku = 284758393
color = "серый"

Базовые многострочные строки

Заключаются в три двойные кавычки. Поддерживают экранирование (\n, \t). Если сразу после открывающих кавычек идет перевод строки, он удаляется (это называется "trimmed").
text = """
Это первая строка.
Это вторая строка с табуляцией: 	конец.
"""

Литеральные многострочные строки

Заключаются в три одинарные кавычки. Экранирование полностью отключено. Это идеальный выбор для путей в Windows, регулярных выражений или вставки фрагментов кода..
regex = '''I [dw]on't need \d{2} apples'''
win_path = '''C:\Users\Admin\Documents'''

Обратный слэш для переноса строки

Заключаются в три одинарные кавычки. Экранирование полностью отключено. Это идеальный выбор для путей в Windows, регулярных выражений или вставки фрагментов кода..
long_string = "The quick brown \
fox jumps over \
the lazy dog."

Директивы (Key-Value pairs)

Это пары «ключ = значение». Знак равенства является разделителем. В классическом INI пробелы вокруг знака = обычно игнорируются, но для читаемости их принято ставить. 
host = "127.0.0.1"
port = 8080
# Режим работы: development или production
environment = "development"

Комментарии

Символ # комментирует всё, что идет за ним до конца строки. 
# ===========================
# Настройки веб-сервера
# ===========================
# Режим работы: development или production
# environment = "development"
environment = "production"

Типизация данных.

Строгая. true — это булево значение, "true" — строка, 123 — число. Формат чувствителен к регистру. 
enabled = true # булевое
model = "true" # текстовое
name = "Гвоздь" # текстовое
sku = 284758393 # числовое значение
price = 15.99 # числовое значение
date = 1979-05-27T07:32:00Z # Дата в формате ISO 8601

Преймущества

  • Однозначность и строгая типизация (Predictability)
  • Читаемость и минимализм (для плоских структур)
  • Явная иерархия

Недостатки

  • Многословность при глубокой вложенности
  • Отсутствие нативного типа null
  • Отсутствие ссылок и переменных

XML

XML — это расширяемый язык разметки, который долгое время был корпоративным стандартом для обмена данными и конфигурации сложных систем (например, Java EE, Spring, .NET). В отличие от INI или TOML, XML является настоящим языком разметки, где данные описываются иерархией тегов.


    
        development
    
    
        postgresql
        db.internal.local
        5432
        app_db
        
            app_user
            secret_password
        
    
    
        /var/log/myapp
        /tmp/myapp

Теги (Элементы)

Данные заключаются в открывающие и закрывающие теги. Всё, что находится между ними, — это содержимое элемента (текст или другие вложенные теги).
db.internal.local

Атрибуты

Дополнительная информация о элементе, записываемая внутри открывающего тега в виде имя="значение".
db.internal.local

Иерархия (Вложенность)

Иерархия (Вложенность) Главная особенность XML — возможность создавать бесконечно глубокие древовидные структуры.

    
        ...

Комментарии

Используются теги . Они могут быть многострочными.

...

Инструкции обработки

Файл часто начинается с декларации версии и кодировки: . Используется для совместимости.

Преимущества

  • Строгая иерархия и расширяемость
  • Надежная валидация
  • Возможна строгая типизация

Недостатки

  • Избыточность (Многословность)
  • Отсутствие комментариев в значениях

YAML

YAML (YAML Ain't Markup Language) — это современный формат сериализации данных, который стал стандартом де-факто для конфигураций в мире DevOps, CI/CD и облачных технологий (Kubernetes, Docker Compose, Ansible, GitHub Actions).
# ===========================
# Метаданные приложения
# ===========================
app:
  name: "My Awesome Service"
  version: "2.1.0"
  # Используем многострочную строку для описания
  description: |
    Это подробное описание сервиса.
    Оно может занимать несколько строк.
    Все переносы строк будут сохранены.

# Простой список строк
features:
  - "Authentication"
  - "Metrics"
  - "Tracing"
# Массив таблиц (список объектов) - аналог JSON-массива объектов
servers:
  - name: "web-01"
    ip: "10.0.0.10"
    role: "frontend"
    
  - name: "web-02"
    ip: "10.0.0.11"
    role: "frontend"

# Определяем общие настройки логирования с помощью якоря (&)
logging: &default_logging
  level: "INFO"
  format: "json"
  file: "/var/log/app/app.log"

# Используем якорь в секции production и добавляем новое поле
production:
  <<: *default_logging  # Вливаем всё из default_logging
  level: "ERROR"        # Переопределяем только уровень
  # Поле 'format' и 'file' возьмутся из якоря

Отступы (Иерархия)

Вложенность определяется исключительно отступами (пробелами). Использование табуляции (Tab) официально запрещено спецификацией YAML 1.2 — это самая частая причина ошибок.
server: # Уровень 0
  host: localhost  # Уровень 1
  database:        # Уровень 1
    name: app_db   # Уровень 2
    port: 5432     # Уровень 2

Комментарии

Символ # комментирует всё, что идет за ним до конца строки.
# =========================== # Метаданные приложения # ===========================
app: name: "My Awesome Service"
version: "2.1.0" # Используем многострочную строку для описания
# debug: true # закомментировано (не используется)

Типы данных (Неявная типизация)

Парсер сам угадывает тип данных.
server:
  version: 1.10 # Число с плавающей точкой
  version: "1.10" # Строка
  port: 8080 # Число
  enable: true # Булево значение
  host: localhost  # Строка
  name: "true"   # Строка
  port: 5432     # Число

Структуры

Поддерживаются словари (множество ключ- значение, в том числе вложенные словари) и списки (множество значений). Списки (Sequences): начинаются с дефиса -.
server: # словарь (таблица)
  host: localhost
  port: 5432
  credentials: # вложенный словарь (подтаблица)
    user: "app_user"
	password: ${DB_PASSWORD}
# Простой список строк 
features:
  - "Authentication"
  - "Metrics"
  - "Tracing"
# Массив таблиц (список объектов)
servers:
  - name: "web-01"
    ip: "10.0.0.10"
    role: "frontend"
  - name: "web-02"
    ip: "10.0.0.11"
    role: "frontend"

Литеральные многострочные строки

Многострочные строки задаются с помощью "пайпа" |. Также для удобства можно многострочно написать одну строку используя > (меняет переносы строк на пробелы)
description: | 
  Это подробное описание сервиса.
  Оно может занимать несколько строк.
  Все переносы строк будут сохранены.

# Это подробное описание сервиса.
# Оно может занимать несколько строк.
# Все переносы строк будут сохранены.
description_string: >
  Это описание сервиса.
  Оно может занимать несколько строк,
  но все переносы строк будут заменены на пробелы.

# Это описание сервиса. Оно может занимать несколько строк, но все переносы строк будут заменены на пробелы.

Якоря (Anchors) и Псевдонимы (Aliases)

Уникальная возможность для переиспользования блоков конфигурации.
defaults: &base # Определяем общие настройки логирования с помощью якоря (&)
  timeout: 30
  retries: 3
  debug: true

production:
  <<: *base  # Используем якорь в секции production и добавляем новое поле
  host: prod.server
  debug: false # Переопределяем поле debug

staging: *base # Используем тот же якорь для staging без изменений

# Результат:
# prod:
#   timeout: 30
#   retries: 3
#   host: prod.server
#   debug: false
# staging:
#   timeout: 30
#   retries: 3
#   debug: true

Преимущества

  • Максимальная читаемость
  • Выразительность
  • Выразительность: Поддержка сложных структур, ссылок (якорей) и мультидокументов (несколько --- в одном файле).

Недостатки

  • Хрупкость (Проблема пробелов)
  • Отсутствие строгой типизации

JSON

JSON (JavaScript Object Notation) — это легковесный текстовый формат обмена данными, основанный на подмножестве языка программирования JavaScript. Несмотря на название, он полностью независим от языка и является стандартом де-факто для API, конфигураций и хранения данных.
{
  "app": {
    "name": "My Awesome Service",
    "version": "2.1.0",
    "debug": false
  },
  "server": {
    "host": "0.0.0.0",
    "port": 8080
  },
  "database": {
    "type": "postgresql",
    "host": "db.internal.local",
    "port": 5432,
    "name": "app_db",
    "credentials": {
      "user": "app_user",
      "password": "secret_password"
    }
  },
  "features": [
    "Authentication",
    "Metrics",
    "Tracing"
  ],
  "threshold": null
}

Объекты (Objects)

Объект — это неупорядоченный набор пар «ключ: значение», заключенный в фигурные скобки {}. Ключ всегда должен быть строкой в двойных кавычках.
{
  "host": "localhost",
  "port": 8080,
  "enabled": true
}

Массивы (Arrays)

Массив — это упорядоченный список значений, заключенный в квадратные скобки []. Значения могут быть любого типа, включая вложенные объекты.
{
  "servers": [
    { "name": "web-01", "ip": "10.0.0.1" },

    # Логирование

                      '$status $body_bytes_sent "$http_referer" '
                      '"$http_user_agent"';

    # Глобальные настройки
    sendfile        on;
    keepalive_timeout  65;

    # Виртуальный хост

        listen       80;
        server_name  example.com www.example.com;
        root         /var/www/html;
        index        index.html index.htm;

        # Настройка отдачи статики
        location / {
            try_files $uri $uri/ =404;
        }

        # Настройка проксирования (backend)

            proxy_set_header X-Real-IP $remote_addr;
